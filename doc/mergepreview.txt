1. Intro                                                *mergepreview-intro*

|mergepreview| opens a three-pane layout that answers three questions about a
feature branch at once:

  * what files changed vs. the branch it was cut from?
  * which commits on the branch touched the currently open file?
  * which commit produced the diff chunk under the cursor?

Base branch detection picks the *nearest ancestor* of HEAD: for every local
branch and `origin/HEAD`, `origin/main`, `origin/master`, `origin/develop`,
the plugin computes the merge-base with HEAD and selects the branch whose
`<merge-base>..HEAD` count is smallest. This is the branch HEAD was most
recently cut from: usually `main`/`master`, but the correct intermediate
branch in stacked or `develop`-based workflows. Ties prefer `main` >
`master` > `develop`. Override by passing an argument to |:MergePreview| or
by setting |g:merge_preview_base|.

==============================================================================
2. Commands                                             *mergepreview-commands*

                                                        *:MergePreview*
:MergePreview [base]    Open the preview in a new tabpage. Without [base] the
                        plugin auto-detects it.

                                                        *:MergePreviewClose*
:MergePreviewClose      Tear down the layout, wipe plugin buffers, close the
                        tabpage.

                                                        *:MergePreviewToggle*
:MergePreviewToggle     Cycle the file view through the available modes in
                        this order, skipping any whose tool is not on $PATH:

                          diff    - side-by-side Vim diff (built-in)
                          difft   - side-by-side structural diff (requires
                                    `difft`, i.e. difftastic; uses
                                    `--display json` and renders aligned
                                    buffers with Vim text properties)
                          plain   - raw unified diff with filetype=diff

==============================================================================
3. Layout                                               *mergepreview-layout*
>
    +-- Files --------+---- File view -------+-- Commits ------------+
    | Changes: feat   | diff / difft /       | Commits touching      |
    | vs main         | plain                | foo.py (main..HEAD)   |
    |-----------------|                      |-----------------------|
    |* M foo.py       |                      |> abc1234 Add X        |
    |  A bar.go       |                      |> def4567 Fix edge     |
    |  M baz.md       |                      |> 7f9a224 Refactor     |
    +-----------------+----------------------+-----------------------+
<
The files and commits panels have a title line and rule at the top so they
read independently of any window tabline or menubar above them.

Commits panel uses native folding: subject lines are fold headers, the body
lines are the fold content. Use the standard fold keys (|zo|, |zc|, |za|,
|zM|, |zR|). The title lines stay at fold level 0 — they are never folded
into the first commit's body.

==============================================================================
4. Mappings                                             *mergepreview-mappings*

Files panel:
  <CR> / o      Open the file under the cursor in the middle pane.
  q             Close the session.

File view:
  ]c            Jump to next hunk; move the commits cursor to its commit.
  [c            Previous hunk; same highlight behavior.
  <leader>mt    Toggle file-view mode.
  <leader>mq    Close the session.

Commits panel:
  <CR>          Show the selected commit in a new tab (via `git show`).
  za / zo / zc  Toggle / open / close the body of one commit (Vim built-in).
  zM / zR       Collapse all / expand all (Vim built-in).
  q             Close the session.

==============================================================================
5. Options                                              *mergepreview-options*

                                                *g:merge_preview_base*
Default: ''.
When non-empty, used as the base branch unless an explicit argument is passed
to |:MergePreview|.

                                          *g:merge_preview_diffopt_extras*
Default: `linematch:60,algorithm:histogram,indent-heuristic,inline:char`
Comma-separated list of |diffopt| values the plugin appends on session open
and restores on close. Values unsupported by the running Vim are silently
skipped (e.g. `inline:char` was added in 9.1.1243).

All file-view modes render into ordinary buffers (`buftype=nofile`), not
terminals. `diff` and `difft` both produce two vertical splits inside the
file-view pane; `plain` and `difft`-fallback produce a single buffer. Hunk
navigation (|]c| / |[c|), search, yank and the normal motions all work.

==============================================================================
6. Dependencies                                         *mergepreview-dependencies*

Required:
  * Vim 8.1+ with |+textprop| for `difft` highlight placement; `diff` and
    `plain` work on earlier Vims.
  * `git` on $PATH.

Optional:
  * difftastic / difft (https://github.com/Wilfred/difftastic): enables the
    structural side-by-side mode. Needs v0.50+ for `--display json`.
  Missing tools are silently skipped by the toggle.

==============================================================================
7. How it works                                         *mergepreview-internals*

All view data derives from a single merge-base:
  * files:   `git diff --name-status <merge-base>...HEAD`
  * commits: `git log <merge-base>..HEAD -- <file>`
  * hunks:   `git diff --unified=0 <merge-base>...HEAD -- <file>`
  * blame:   `git blame --porcelain -L n,n HEAD -- <file>` (filtered to the
             commits in <merge-base>..HEAD).

Blame results are filtered to commits within the range, so lines that existed
on the base branch do not highlight a commit when jumping hunks.

`difft` mode derives its layout from `difft --display json`:
  * `aligned_lines` drives the row alignment between the two scratch
    buffers. Where one side is null, a blank filler row is written so the
    opposite row still matches up.
  * `chunks[*][*].{lhs,rhs}.changes[]` drives per-line highlights via
    |prop_add()|. Difft's `highlight` enum values are mapped to Vim groups
    (novel -> DiffAdd, changed -> DiffText, delimiter -> Delimiter,
    string-partial -> String, type-partial -> Type). Unknown values fall
    back to DiffText.
  * `scrollbind` and `cursorbind` (no |:diffthis|) keep the two panes in
    sync — difft has already computed the alignment, so Vim's diff engine
    would just re-diff the rows and fight difft's intent.
